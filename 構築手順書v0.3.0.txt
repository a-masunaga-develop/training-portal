# Training Portal v0.3.0 開発計画（確定版）

## 概要

v0.3.0では、研修ポータルを「Phase管理システム」から「コンテンツ単位の学習管理システム」へ進化させる。

これまでの設計では、Phase完了を基準としていたが、実際の学習ではコンテンツごとの理解度確認が重要である。

そのため、

学習
↓
テスト
↓
合格
↓
完了

という学習サイクルをコンテンツ単位で管理する。

---

# v0.3.0 テーマ

「コンテンツ単位の学習管理システムへの進化」

# コンセプト

受講者は以下の流れで学習する。

```text
コンテンツ受講
↓
理解度テスト受験
↓
合格
↓
コンテンツ完了
↓
次のコンテンツへ進む
```

コンテンツ単位で進捗を管理し、学習状況を可視化する。

# 実装メモ（実際の構成）

## 計画からの変更・補足

```text
進捗テーブル   progress（キー userId のみ）はコンテンツ単位にできないため、
               新テーブル content_progress（userId + contentId）を作成。
               旧 progress テーブルは削除せず残す（アプリからは使用しない）。

コンテンツ種別 計画の5種別に text（社内教材）を追加。
               既存の4レッスン（クラウド / IAM / S3 / EC2）を Phase1 の
               text コンテンツ c001〜c004 として移行。

テスト         各コンテンツ3問（既存5問を振り分け、7問を追加）。

受講制御       公開中のフェーズ順 → コンテンツ順に並べ、前を完了しないと
               次は開けない（フェーズをまたいで順番に進む）。
               admin は非公開・未解放もプレビュー可能。

完了条件       問題あり：テストで合格点以上 → completed
               問題なし：「学習完了にする」ボタン → completed
               合格後に再受験して不合格でも completed のまま（最高得点を保持）

状態の記録     コンテンツを開く → learning、テスト画面を開く → testing

受講者管理     一覧・受講者別の進捗確認まで。
               Cognito ユーザーの作成は画面からは行わない（権限追加が必要なため）。
```

## 画面

```text
/phases                        学習コンテンツ一覧（フェーズ別、状態・解放状況）
/contents/[contentId]          学習画面（YouTube は埋め込み、その他はリンク）
/contents/[contentId]/test     理解度テスト・受験履歴
/admin                         概要（最新テスト結果・日報）
/admin/phases                  Phase管理
/admin/contents                コンテンツ管理（一覧・追加・編集・削除）
/admin/contents/[contentId]    コンテンツ編集＋テスト管理（問題の追加・編集・削除）
/admin/students                受講者一覧・コンテンツ別進捗
/admin/students/[userId]       受講者ごとの進捗・テスト結果・日報

/phase1 と /test は /phases へ転送
```

## DynamoDB テーブル

```text
phases            phaseId
contents          contentId
tests             testId（contentId 属性を追加）
test_results      resultId（contentId / passed / passScore / attempts を追加）
content_progress  userId + contentId（新規）
```

## AWS 反映手順

1. admin ユーザーで IAM ポリシーを更新（develop ユーザーは IAM を変更できない）

```text
TrainingPortalDynamoDBAccess（コンピューティングロール）
  → infrastructure/iam/amplify-compute-role-policy.json の内容で新しいバージョンを作成
    （新テーブル3つと、DeleteItem / Query を追加）

TrainingPortalDeveloper（develop-group）
  → infrastructure/iam/training-portal-developer-policy.json の内容で新しいバージョンを作成
    （新テーブル3つを追加）
```

2. テーブル作成と初期データ投入（develop ユーザー）

```powershell
& "C:\Program Files\Git\bin\bash.exe" ./infrastructure/dynamodb/init.sh --aws
& "C:\Program Files\Git\bin\bash.exe" ./infrastructure/dynamodb/seed.sh --aws phases contents tests
```

users は上書きしないよう、投入するテーブルを指定する。

3. feature/content-management → develop → main にマージ（Amplify が自動ビルド）
