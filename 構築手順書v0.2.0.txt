# Training Portal v0.2.0 開発計画

## 概要

v0.1.0では研修ポータルのMVPを構築し、AWS Amplify上で公開した。

v0.2.0では実運用に向けた最初の機能拡張として、認証・認可機能を実装する。

---

## 目的

現在の課題

- 誰でもURLアクセス可能
- ユーザー識別ができない
- 管理者と受講者の権限制御がない
- 学習履歴と利用者が紐付かない

これらを解決する。

## AWS構築作業

### Cognito User Pool作成

名称

```text
training-portal-users
```

設定

- Emailログイン
- パスワードポリシー有効（8文字以上・英大文字・英小文字・数字）
- MFAなし（MVP）
- 自己登録無効（管理者のみユーザー作成可）

作成結果

```text
User Pool ID : ap-northeast-1_WIFdomguf
```

実行コマンド（AWS CLI）

```bash
aws cognito-idp create-user-pool --region ap-northeast-1 \
  --pool-name training-portal-users \
  --username-attributes email --auto-verified-attributes email \
  --policies 'PasswordPolicy={MinimumLength=8,RequireUppercase=true,RequireLowercase=true,RequireNumbers=true,RequireSymbols=false,TemporaryPasswordValidityDays=7}' \
  --admin-create-user-config AllowAdminCreateUserOnly=true \
  --mfa-configuration OFF \
  --account-recovery-setting 'RecoveryMechanisms=[{Priority=1,Name=verified_email}]'
```

---

### App Client作成

名称

```text
training-portal-web
```

設定

- クライアントシークレットなし（ブラウザから利用するため）
- 認証フロー：ALLOW_USER_SRP_AUTH / ALLOW_REFRESH_TOKEN_AUTH
- ユーザー存在エラーの防止：有効

作成結果

```text
User Pool ID : ap-northeast-1_WIFdomguf
Client ID    : 66qked8uk0ofs249iih2vomik0
```

環境変数へ登録する。

実行コマンド（AWS CLI）

```bash
aws cognito-idp create-user-pool-client --region ap-northeast-1 \
  --user-pool-id ap-northeast-1_WIFdomguf \
  --client-name training-portal-web \
  --no-generate-secret \
  --explicit-auth-flows ALLOW_USER_SRP_AUTH ALLOW_REFRESH_TOKEN_AUTH \
  --prevent-user-existence-errors ENABLED
```

### テストユーザー作成

管理者

```text
admin@example.com
```

受講者

```text
student@example.com
```

仮パスワードで作成し、初回ログイン時に本人が新しいパスワードを設定する。
example.com はメールを受信できないため、招待メールは送信しない（SUPPRESS）。
仮パスワードの有効期限は7日間。

※ 仮パスワードはこの手順書やリポジトリに記載しない。

実行コマンド（AWS CLI、ユーザーごとに実行）

```bash
aws cognito-idp admin-create-user --region ap-northeast-1 \
  --user-pool-id ap-northeast-1_WIFdomguf \
  --username student@example.com \
  --user-attributes Name=email,Value=student@example.com Name=email_verified,Value=true \
  --temporary-password '<仮パスワード>' \
  --message-action SUPPRESS

aws cognito-idp admin-add-user-to-group --region ap-northeast-1 \
  --user-pool-id ap-northeast-1_WIFdomguf \
  --username student@example.com --group-name student
```

仮パスワードの有効期限が切れた場合は、--message-action RESEND ではなく
admin-set-user-password（--no-permanent）で仮パスワードを再設定する。

### API の権限

```text
GET  /api/users          admin のみ
GET  /api/reports        student：自分の日報 / admin：全件（?userId= で絞込）
GET  /api/test-results   student：自分の結果 / admin：全件（?userId= で絞込）
GET  /api/progress       student：自分の進捗 / admin：全件（?userId= で絞込）
GET  /api/tests          ログインユーザー全員
POST /api/reports        ログインユーザー自身の日報として保存
POST /api/test-results   ログインユーザー自身の結果として保存
POST /api/progress       ログインユーザー自身の進捗として保存
```

## 環境変数

Amplifyへ追加（ホスティング → 環境変数）

```text
AMPLIFY_MONOREPO_APP_ROOT=frontend

APP_ENV=prod

APP_REGION=ap-northeast-1

NEXT_PUBLIC_COGNITO_USER_POOL_ID=ap-northeast-1_WIFdomguf

NEXT_PUBLIC_COGNITO_CLIENT_ID=66qked8uk0ofs249iih2vomik0

USERS_TABLE=users

REPORTS_TABLE=reports

TESTS_TABLE=tests

PROGRESS_TABLE=progress

TEST_RESULTS_TABLE=test_results
```

注意

- AWS_ で始まる環境変数は Amplify の予約語のため登録できない。
  リージョンは AWS_REGION ではなく APP_REGION で指定する。
- Amplify の環境変数は amplify.yml のビルド時に .env.production へ書き出し、
  Next.js から読めるようにしている（NEXT_PUBLIC_ で始まる変数も対象）。
- AWS CLI の update-app --environment-variables は全件置き換えになるため、
  既存の変数もすべて指定する。

ローカル（frontend/.env.local）

```text
APP_ENV=local
AWS_REGION=ap-northeast-1
DYNAMODB_ENDPOINT=http://localhost:8000
AWS_ACCESS_KEY_ID=test
AWS_SECRET_ACCESS_KEY=test
NEXT_PUBLIC_COGNITO_USER_POOL_ID=ap-northeast-1_WIFdomguf
NEXT_PUBLIC_COGNITO_CLIENT_ID=66qked8uk0ofs249iih2vomik0
```

Cognito にはローカル用のエミュレーターがないため、ローカル開発でも AWS の Cognito を利用する。

## DynamoDB拡張

usersテーブル項目追加

```json
{
  "userId": "u001",
  "email": "student@example.com",
  "name": "Yamada Taro",
  "role": "student"
}
```

ログイン時、Cognito のメールアドレスで users テーブルを検索し、userId を特定する。
既存の日報・テスト結果・進捗（userId=u001 など）はそのまま引き継がれる。

管理者用レコードも追加する。

```json
{
  "userId": "a001",
  "email": "admin@example.com",
  "name": "Admin",
  "role": "admin"
}
```

ローカル（DynamoDB Local）

```text
infrastructure/dynamodb/seed/users.json を更新済み
./infrastructure/dynamodb/seed.sh で投入
```

AWS（users テーブルのみ更新。seed.sh --aws は tests / progress も上書きするため使わない）

```powershell
aws dynamodb update-item --table-name users --key '{\"userId\":{\"S\":\"u001\"}}' --update-expression "SET email = :e" --expression-attribute-values '{\":e\":{\"S\":\"student@example.com\"}}' --region ap-northeast-1

aws dynamodb put-item --table-name users --item '{\"userId\":{\"S\":\"a001\"},\"email\":{\"S\":\"admin@example.com\"},\"name\":{\"S\":\"Admin\"},\"role\":{\"S\":\"admin\"}}' --region ap-northeast-1
```
